Part 1: Mapping Basics

What Is GIS?

Geographic Information Systems = data + location

  • Any dataset with a spatial component can be put on a map
  • Agriculture is inherently spatial: counties, farms, markets, watersheds, supply chains
  • Maps reveal patterns that tables and charts simply cannot

Today’s goal: get you from zero to a working map pipeline in R

GIS has historically required specialized software (ArcGIS, QGIS). R has changed that dramatically. You can do most of what you’d do in ArcGIS from a .R script.

Types of Spatial Data

Vector data (what we’ll use today)

Type Examples
Points farmers markets, food hubs, farms
Lines roads, rivers, rail corridors
Polygons counties, states, ZIP codes

Raster data (not today)

  • A grid of cells, like a photo
  • Elevation, land cover, satellite imagery, NDVI
  • Handled in R via terra / stars

Almost all the data you’ll encounter in an agricultural economics context is vector data. County-level NASS stats map to polygons. Farmer market locations map to points. You will rarely need raster data unless you’re doing remote sensing work.

What Lives in an sf Object?

An sf (simple features) data frame is just a regular data frame with one extra column: geometry

Simple feature collection with 3,234 features
Geometry type: MULTIPOLYGON
CRS: NAD83 (EPSG:4269)

   GEOID  NAME         STATEFP  ALAND        geometry
1  01001  Autauga      01       1539602840   MULTIPOLYGON(...)
2  01003  Baldwin      01       4117521611   MULTIPOLYGON(...)
3  01005  Barbour      01       2291820706   MULTIPOLYGON(...)

All your normal dplyr verbs work on it. The geometry column just comes along for the ride.

This is the key insight that makes R spatial data so ergonomic. You don’t need to learn a completely new data model. filter(), mutate(), left_join() all work exactly as you’d expect.

Coordinate Reference Systems

The earth is round. Maps are flat. Something has to give.

A CRS defines how 3D coordinates get projected onto a 2D surface.

Three CRS you’ll actually encounter:

CRS EPSG code When you’ll see it
WGS84 4326 GPS coordinates, GeoJSON files, web APIs
NAD83 4269 TIGER/Line files, US government data
Albers Equal Area 5070 National-scale thematic maps

Rule of thumb: for any map showing the whole contiguous US, reproject to Albers (EPSG 5070).

The most common beginner mistake is mixing CRS. If your layers don’t line up, 9 times out of 10 it’s a CRS mismatch. sf will warn you, but always check. The other mistake is leaving Alaska in its native projection, which ends up way too far to the right.

Why Projections Matter

No projection (WGS84 / lat-lon)

  • States look stretched east-west
  • Distances and areas are distorted
  • Fine for quick checks, not for presentation

Albers Equal Area (EPSG 5070)

  • Shapes look familiar
  • Areas are preserved (critical for choropleth maps)
  • The standard for US national maps

“Equal area” projections are especially important for choropleths. If you don’t use one, large counties will visually dominate the map regardless of the data values.

Types of Maps

Map type Best for Watch out for
Choropleth Rates, percentages, densities Raw counts favor large areas
Dot / point Individual locations Overplotting at high density
Proportional symbol Totals, counts by location Symbol overlap in dense areas
Reference / base Context, navigation Adding too much detail

For local food data: choropleths (county-level rates/shares) and point maps (market/hub locations) will cover the majority of your needs.

One of the most common mapping mistakes I see in academic work: mapping raw counts on a choropleth. If Wyoming has 10 SNAP households, that looks tiny compared to Cook County (Chicago) with 300,000. But Wyoming also has far fewer total households. Always normalize. Show rates, shares, or densities—not raw numbers—unless you’re specifically making a point about total volume.

Part 2: Mapping in ggplot2

The Building Blocks

library(tidyverse)
library(sf)
library(tigris)

options(tigris_use_cache = TRUE)
  • tidyverse: data manipulation + ggplot2
  • sf: spatial data as data frames
  • tigris: US Census TIGER/Line boundaries, straight into R

tigris_use_cache is important: it saves files locally so you don’t re-download them every time you render.

Getting Boundary Data

# State boundaries
states_sf <- states(cb = TRUE, resolution = "20m") |>
  filter(!STUSPS %in% c("AK", "HI", "PR", "VI", "GU", "AS", "MP"))

# County boundaries
counties_sf <- counties(cb = TRUE, resolution = "20m") |>
  filter(!STATEFP %in% c("02", "15", "72", "78", "66", "60", "69"))
  • cb = TRUE: simplified cartographic boundary (smaller file, better for maps)
  • resolution = "20m": 1:20,000,000 scale (good for national maps)
  • The filter removes Alaska, Hawaii, and territories

There are also more detailed options: resolution = “5m” and “500k”. For a full-country map you almost never need anything finer than “20m”. Also note: tigris has many other geographies (tracts, block groups, places, school districts, congressional districts, ZIP codes, etc.).

Your First Map

ggplot(states_sf) +
  geom_sf()

That’s the whole thing. geom_sf() reads the geometry column and draws the shapes.

[Run this live.] Notice it looks weird: the projection is off. States look stretched. Let’s fix that next.

Applying a Projection

ggplot(states_sf) +
  geom_sf() +
  coord_sf(crs = 5070)

coord_sf() reprojects the visualization without modifying your data.

Compare: - No coord_sf() → lat-lon, states look stretched east-west - coord_sf(crs = 5070) → Albers Equal Area, looks like a US atlas

[Run this live, showing before and after.] The difference is dramatic. This is the single most impactful improvement you can make to a US national map.

Making It Look Nice

ggplot(states_sf) +
  geom_sf(
    fill  = "white",
    color = "gray40",
    linewidth = 0.3
  ) +
  coord_sf(crs = 5070) +
  theme_void()
  • fill: interior color
  • color: border color
  • linewidth: border thickness
  • theme_void(): removes axes, gridlines, background

theme_void() is almost always what you want for a finished map. theme_minimal() works too if you want a subtle grid.

Adding Data: The Choropleth

ggplot(counties_sf) +
  geom_sf(aes(fill = ALAND), color = NA) +
  coord_sf(crs = 5070) +
  scale_fill_viridis_c(name = "Land area") +
  theme_void()
  • aes(fill = ALAND): map the land area variable to fill color
  • color = NA: drop county borders (they clutter national maps)
  • scale_fill_viridis_c(): perceptually uniform, colorblind-safe

The fill aesthetic works the same way as in any other ggplot.

[Run this live.] ALAND is the land area column that comes with tigris counties, useful for this demo because we don’t need to load any external data. In your actual work, you’ll join your own data to counties_sf, then map one of those columns.

Joining Your Data to a Map

my_data <- read_csv("local_food_data.csv")  # has a column called GEOID

county_map <- counties_sf |>
  left_join(my_data, by = "GEOID")

ggplot(county_map) +
  geom_sf(aes(fill = local_food_sales_per_farm), color = NA) +
  coord_sf(crs = 5070) +
  scale_fill_viridis_c(labels = scales::dollar) +
  theme_void() +
  labs(title = "Local Food Sales per Farm by County")

The GEOID is a 5-character FIPS code: 2-digit state + 3-digit county.

This is the workflow you’ll use for your challenge data. Get county boundaries from tigris, join your data on GEOID, then map it. The key is making sure your GEOID column is formatted correctly: zero-padded, character type, not numeric.

Choosing a Color Scale

# Perceptually uniform (good default)
scale_fill_viridis_c(option = "magma")

# ColorBrewer sequential
scale_fill_distiller(palette = "YlOrRd", direction = 1)

# Diverging: good when data has a meaningful midpoint (e.g., above/below zero)
scale_fill_distiller(palette = "RdBu", direction = 1)

# When data is right-skewed, transform the scale
scale_fill_viridis_c(trans = "log10", labels = scales::comma)

Avoid rainbow palettes (rainbow(), jet). They are not perceptually uniform and can create false visual boundaries in your data.

ColorBrewer (RColorBrewer package, or built into ggplot via scale_fill_distiller) was designed specifically for maps. The palettes are proven to work across different display conditions and are accessible to colorblind viewers.

Adding a Second Layer

ggplot() +
  geom_sf(data = county_map,
          aes(fill = local_food_sales_per_farm),
          color = NA) +
  geom_sf(data = states_sf,
          fill  = NA,
          color = "white",
          linewidth = 0.4) +
  coord_sf(crs = 5070) +
  scale_fill_viridis_c(labels = scales::dollar) +
  theme_void()

State outlines on top of county fill = clean, readable national map.

This two-layer trick is standard for national maps. The county choropleth is the bottom layer; the state outlines float on top in white so they’re visible but not intrusive. Notice we moved the data argument into each geom_sf() call rather than ggplot(), which lets us use different datasets per layer.

Part 3: Census and NASS Data

tidycensus

tidycensus by Kyle Walker pulls Census Bureau data directly into R, with geometry attached.

library(tidycensus)

# One-time setup (get a free key at api.census.gov/data/key_signup.html)
census_api_key("YOUR_KEY_HERE", install = TRUE)

Covers: - Decennial Census (2000, 2010, 2020) - American Community Survey (ACS 1-year and 5-year) - Agricultural data via the Census of Agriculture

The API key is free and instant. Go to api.census.gov, fill out the form, get an email. You only need to install it once; it saves to your .Renviron file.

Finding the Right Variable

# Browse available variables
v22 <- load_variables(2022, "acs5", cache = TRUE)

# Search for what you want
v22 |>
  filter(str_detect(label, regex("snap|food stamp", ignore_case = TRUE))) |>
  select(name, label, concept)

There are ~27,000 ACS 5-year variables. load_variables() + filter() is how you find what you need.

The Census variable naming is… not intuitive. B22003_002 means something if you know the codebook, but you’d never guess it. load_variables() gives you a searchable table. I usually do str_detect() searches on the label column.

Pulling Data with Geometry

snap_households <- get_acs(
  geography = "county",
  variables  = c(snap = "B22003_002",   # households receiving SNAP
                 total = "B22003_001"),  # total households
  year       = 2022,
  geometry   = TRUE                     # returns sf object, no joining needed
)
snap_rate <- snap_households |>
  select(GEOID, NAME, variable, estimate) |>
  pivot_wider(names_from = variable, values_from = estimate) |>
  mutate(snap_pct = snap / total) |>
  filter(!str_starts(GEOID, "02|15|72"))  # drop AK, HI, PR

geometry = TRUE is the killer feature. The sf object comes back ready to map. No shapefile download, no join. It’s all in one call. The pivot_wider step is standard when you pull multiple variables at once; tidycensus returns long-format data by default.

Mapping the Result

ggplot(snap_rate) +
  geom_sf(aes(fill = snap_pct), color = NA) +
  geom_sf(data = states_sf, fill = NA,
          color = "white", linewidth = 0.4) +
  coord_sf(crs = 5070) +
  scale_fill_viridis_c(
    name   = "Share of households\nreceiving SNAP",
    labels = scales::percent_format(accuracy = 1),
    option = "magma"
  ) +
  theme_void() +
  labs(title = "SNAP Participation by County (2022 ACS)")

[Run this live.] This is a complete, publication-ready map in about 20 lines of code including the data pull. Note how we normalize: we’re showing the SNAP rate, not the raw count. This is essential for a choropleth of counties that vary dramatically in population.

NASS QuickStats: rnassqs

NASS QuickStats is the USDA’s public database for agricultural statistics: crops, livestock, farm economics, farm counts, and more.

library(rnassqs)

# One-time setup per session (get a free key at quickstats.nass.usda.gov/api)
nassqs_auth("YOUR_API_KEY")

Covers: most Census of Agriculture tables + annual/quarterly survey data

Geographic levels: national, state, district, county, watershed

NASS QuickStats is the programmatic interface to the same data you’d find on the NASS website. For the challenge, you’re probably already familiar with some of these datasets. rnassqs wraps the API and returns clean data frames.

Querying NASS Data

params <- list(
  commodity_desc    = "VEGETABLES",
  statisticcat_desc = "SALES",
  unit_desc         = "$",
  domain_desc       = "TOTAL",
  agg_level_desc    = "COUNTY",
  year              = 2022
)

veg_sales <- nassqs(params)

Use the QuickStats web interface to explore variables and build your query, then translate it to rnassqs parameters.

The parameter names map directly to the column names in the QuickStats web interface. I always prototype queries on the website first, then translate them to code. The website also shows you how many records your query will return (the API has a 50,000-row limit per call).

Joining NASS Data to a Map

NASS returns a plain data frame with no geometry. Build the GEOID and join to counties_sf:

county_veg <- counties_sf |>
  left_join(
    veg_sales |>
      mutate(
        GEOID = paste0(
          str_pad(state_fips_code, 2, pad = "0"),
          str_pad(county_code, 3, pad = "0")
        ),
        value_numeric = as.numeric(str_remove_all(Value, ","))
      ) |>
      select(GEOID, value_numeric),
    by = "GEOID"
  )

Two things to watch: first, NASS suppresses values for privacy: counties with fewer than 3 farms in a category show “(D)” instead of a number. as.numeric() will coerce those to NA, which is correct behavior. Second, always zero-pad your FIPS codes. “1001” and “01001” are different strings; the join will silently fail if you don’t pad.

Mapping the NASS Result

ggplot(county_veg) +
  geom_sf(aes(fill = value_numeric), color = NA) +
  geom_sf(data = states_sf, fill = NA,
          color = "white", linewidth = 0.4) +
  coord_sf(crs = 5070) +
  scale_fill_viridis_c(
    name   = "Vegetable sales ($)",
    labels = scales::dollar_format(scale = 1e-6, suffix = "M"),
    trans  = "log10",
    na.value = "gray90"
  ) +
  theme_void() +
  labs(title = "County-Level Vegetable Sales (2022 Census of Ag)",
       caption = "Source: USDA NASS QuickStats. Suppressed counties shown in gray.")

Two things to point out: trans = “log10” is important here because farm sales data is extremely right-skewed. Without the log transform, everything except a handful of California counties will be the same color. Also note na.value = “gray90” for suppressed counties, and acknowledging suppression in the caption.

Part 4: Interactive Maps

Why Go Interactive?

Static maps are great for publications and reports. Interactive maps let viewers:

  • Zoom in to their own county or region
  • Hover to see exact values
  • Toggle between multiple data layers
  • Explore on their own terms

For a data challenge or a Shiny app, interactive maps dramatically increase engagement.

The tradeoff is file size and rendering. A ggplot map is a static image: tiny, fast, universally portable. An interactive mapgl map is an HTML widget that needs to load JavaScript and tiles. For a Quarto document or webpage, that’s totally fine. For a PDF or Word doc, stick to ggplot.

The mapgl Package

mapgl brings MapLibre GL into R: fast, vector-tile-based interactive maps

library(mapgl)

The core workflow mirrors what we’ve done in ggplot:

ggplot2 mapgl
ggplot() maplibre()
geom_sf(aes(fill = ...)) add_fill_layer()
geom_sf(data = points) add_circle_layer()
scale_fill_viridis_c() interpolate() inside fill_color

mapgl was written by Kyle Walker, same author as tidycensus. It’s designed to work naturally with sf objects and tidyverse data. You can pass any sf data frame directly as the source argument.

An Interactive Choropleth

us48 <- filter(states_sf, !STUSPS %in% c("AK", "HI"))

maplibre(bounds = us48, style = carto_style("positron")) |>
  add_fill_layer(
    id     = "snap_counties",
    source = snap_rate,
    fill_color = interpolate(
      column    = "snap_pct",
      values    = c(0, 0.15, 0.40),
      stops     = RColorBrewer::brewer.pal(3, "YlOrRd"),
      na_color  = "lightgrey"
    ),
    fill_opacity = 0.85,
    tooltip      = "NAME"
  )

[Run this live.] Notice the immediate similarity to the ggplot code. interpolate() is mapgl’s equivalent of scale_fill_viridis_c(): you provide breakpoints (values) and colors (stops). The tooltip argument names the column that shows on hover.

Adding Point Layers

maplibre(bounds = us48, style = carto_style("positron")) |>
  add_fill_layer(
    id     = "snap_counties",
    source = snap_rate,
    fill_color = interpolate(
      column   = "snap_pct",
      values   = c(0, 0.15, 0.40),
      stops    = RColorBrewer::brewer.pal(3, "YlOrRd"),
      na_color = "lightgrey"
    ),
    fill_opacity = 0.7
  ) |>
  add_circle_layer(
    id     = "markets",
    source = farmers_markets_sf,   # your point data
    circle_color  = "#2c5f2e",
    circle_radius = 5,
    circle_stroke_color = "white",
    circle_stroke_width = 1,
    tooltip = "market_name"
  )

Layering in mapgl works the same as ggplot: pipe additional layers on top. Layers are drawn in order: the first add_ call is the bottom layer. Here we’re showing county SNAP rates as the choropleth background, with farmers market locations plotted on top.
